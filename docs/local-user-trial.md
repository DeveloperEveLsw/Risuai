# Local user trial, in development

Run `pnpm trial:local` from this repository with Node 22.12+ and installed pnpm dependencies. The command builds the original entity UI and native engine into a fresh `.local-runtime/trials/trial-*` directory, starts a separate loopback test provider, and creates a new synthetic SQLite database. It prints the URL, the separate trial password `local-trial`, and the data directory. The default URL is `http://127.0.0.1:5176`.

This is a cost-free structural trial. The provider returns authored Korean text after eight seconds and never forwards requests to an actual model. Original native prompt preparation, streaming, output Lua and transaction commits still run. No deployed service, existing save or installed character is opened. Every invocation starts a fresh database; retained data is available for inspection, but this command does not resume an earlier trial.

The trial explicitly selects the original `strong` streaming display mode: partial text is shown directly, and the original output-script pipeline runs at completion. Its initial history window is 30 messages so both trial replies and the image prefix remain rendered. These are fixture configuration choices, not changes to original mode semantics or unlimited history loading.

For a later invocation, use a fresh browser profile or a different unused trial port. The browser pins the database authority for each origin. Reusing the same ordinary profile and port with a new database can report `SERVER_CHANGED`; the trial intentionally preserves this guard and never silently moves old pending inputs into the new database. Incognito storage resets only after every incognito window closes. Do not clear storage for the deployed service to run this loopback trial.

## Try the actual UI

1. Open the printed URL in an ordinary browser window and an incognito window, then sign in with `local-trial` in both. These have independent browser storage, like two device clients. Select **로컬 구조 시험**. Under WSL, the Windows browser can use the forwarded loopback address when WSL localhost forwarding is enabled.
2. Click **동기화 시험 토글**. Its selection should respond immediately and then appear in the other window. Click **카운터 +1** in the greeting; the server runs the original button Lua and both windows should show `카운터: 1` after commit. Button script effects follow the server's ordering for that chat.
3. Send a neutral message using the normal textarea. A new user body can briefly show **메시지 표시 준비 중…** while its original display scripts finish; the input must already be cleared and resized. After an initial display failure, the row reports **메시지를 표시하지 못했습니다.** instead of substituting unprocessed source. Both windows should show `연습 응답 1: 처리 중입니다.` before completion. Change the toggle while it is processing; it should synchronize before the delayed reply finishes. The existing image/message should remain present. After eight seconds, the reply adds `완료했습니다.` and the greeting shows `마지막 응답: 완료`.
4. Send a second message. Once its partial response is visible, close **all trial tabs** while keeping the terminal running. Wait longer than eight seconds, reopen the same URL, and select the character. The completed reply, counter and toggle should return without resending the message.
5. Use the character's chat list to select **독립 채팅**. It has separate message history and counter variables. Requests in different chats can execute independently; requests in the same chat retain their order.
   The character's **Lorebook** editor also contains **합성 로어 편집 시험**. Change its name/content in one profile and inspect it in the other. Enable **Always Active (Current Chat)** and inspect the Chat lore tab; its reference belongs to that chat. The original settings, folders and JSON import/export controls use server commands. See [lore editor boundaries and remaining limits](server-lore-editors.md).
   Under **Advanced Settings**, edit a synthetic prompt field, depth prompt, creator notes or bias and inspect its confirmed value in the other profile. Add/reorder/remove **합성 대체 인사**; removal also resets this chat's selected greeting. Existing notes should not be rewritten merely by opening the page. Missing creator/version/depth metadata should display defaults and create fields only when edited. See [definition editor boundaries](server-character-definition-editors.md) and [encoding performance limits](field-draft-performance.md).
   Under **Character Display**, select an authored image, change a spare icon or emotion name, and upload/rename/remove an additional asset in one profile. Inspect the other profile and reload it. File selection captures its opening owner, and a competing change rejects attachment. Additional-asset removal also resets the current chat's selected greeting. See [asset editor procedure and limits](server-character-assets.md). The user excluded further TTS work and trial acceptance; leave automatic TTS disabled.
   Under **Advanced Settings**, use **Convert to Module** on the synthetic character, then open **Apply Module** in the other profile to find the converted item. Conversion preserves the original mapped scripts and indicator lore without changing the source. Applying appends a copy of lore/regex/triggers; repeated application intentionally repeats those original items. The chat composer's menu → **Modules** separately toggles activation; a normal click belongs to the current chat, and the original context-menu action belongs to the character. See [module action boundaries](server-character-module-actions.md).
6. Press Ctrl+C in the terminal to stop the trial UI, native runtime and test provider. The fresh data directory remains. Do not treat its synthetic content as an original save backup.

Use `RISU_LOCAL_TRIAL_PORT=5177 pnpm trial:local` if the default port is occupied. An occupied port causes a startup error and leaves the existing listener running. `RISU_LOCAL_TRIAL_DELAY_MS` accepts 0–30000; `RISU_LOCAL_TRIAL_PARENT` changes the parent for new directories. Normal use should keep the default parent inside this repository so the isolated native bundle can resolve its installed dependencies. A parent outside it needs compatible dependency resolution.

For an already built entity UI, `node server/runtime/localTrial.cjs --built-ui PATH` skips builds and uses `server/native/dist/extensionJob.mjs`; this diagnostic shortcut requires an existing matching native build. The default command isolates both builds, so subsequent development builds cannot replace the running trial's native bundle. Stopping during a build also stops its own build process.

## Validation and limits

`server/runtime/localTrial.test.cjs` covers provider bounds and SSE/JSON, fresh databases, authentication, duplicate admission, two simultaneous native generations, output Lua, isolated native bundle loading, occupied ports, build cancellation and shutdown. `server/browser/localTrialUi.test.cjs` exercises this CLI and the optimized original UI with independent Chromium contexts, normal textarea sends, peer toggles while generation runs, native HTML button/output Lua, retained row/image DOM objects, closing every trial tab, and canonical reply restoration without extra provider calls.

To run the browser case including both default builds, use `RISU_LOCAL_TRIAL_BUILD=TRUE node --test server/browser/localTrialUi.test.cjs`. `RISU_BROWSER_CHROMIUM` selects an installed Chromium executable. With `RISU_DISPLAY_WORKER_BUILD_PATH`, the case instead exercises the already-built shortcut. Test-owned databases/profiles/builds are removed after their processes close; the ordinary CLI retains its new database.

This loopback trial does not expose a physical phone or LAN endpoint. Independent desktop browser contexts prove the specified synchronization and tab-exit flows, not physical mobile suspension, offline initial startup or universal conflict freedom. The tiny authored fixture does not prove representative latency or eliminate the previously measured large-fixture stuttering. Full resource-read provenance, faithful editing/import/export across remaining screens, provider/plugin/Python/asset host capabilities and all 15 original completion requirements remain open. See [server-runtime-plan.md](server-runtime-plan.md).

Initial attempts are retained in the validation evidence. With the fixture's history window set to1, the prefix leaves the two-row render window when new messages arrive. A separate browser diagnostic decoded both the earlier imperfect PNG byte sequence and its replacement; it disproved image decoding as the cause of the removed row. After correcting the window, `off` mode still kept the newly generated body waiting for canonical display preparation even though durable native progress already contained the partial text. The trial's strong-mode acceptance does not establish that `off` streaming is fully responsive.

The separate actual-source display wrapper diagnostic found that long Lua bodies inside frozen effect arrays do not grow scope-key serialization; long shallow trigger comments do. No display performance algorithm was changed for this trial, and no new speedup is claimed.
