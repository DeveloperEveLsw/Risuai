# Yield after capturing display context

Entity-mode ParseMarkdown yields to a browser task after pinning its private character/message/read context, settings and finalizer. It then performs the original asset and script pipeline. The existing yieldDisplayTurn uses scheduler.yield where available, with setTimeout otherwise. Legacy parsing and all CBS/regex/Lua calculations remain unchanged. It does not move browser presentation onto the server.

An actual original-UI diagnostic on commit 2d3cecb found a 386.375ms microtask checkpoint under page CPU throttling by four. That interval contained no recorded ParseHTML/Layout/Paint events. Immediately fulfilled asset/pre-Lua promises and Svelte continuations could keep preparation inside the same checkpoint. The new boundary allows rendering/input tasks to run before that preparation resumes, without recapturing changing DBState after the wait.

The same synthetic fixture compared six warm baseline samples with six virtual-source candidate samples in each scenario. The maximum frame gap under page throttling fell from 366.6ms to 200ms. The maximum time to settled display increased from 1409ms to 1445.6ms, and maximum immediate feedback time increased from 49ms to 58.7ms. Desktop frame gaps were 100.1ms and 100ms. Every sample retained 56 original Lua computations, including 44 unrelated rows. This is a scheduling tradeoff, not a claim that scripts finish faster or that all cards have no stutter. The virtual prototype remains separately recorded as a prototype; fresh current-source acceptance has its own evidence.

The actual original parser fixture holds the scheduler capability after capture, changes quote/image settings through durable resource field commands, and releases the old task. Old preparation retains its captured quotation marks and asset; a new timer-fallback preparation uses the changed settings and hides images. The false current-owner finalizer returns undefined. Canonical message text/revision remain unchanged. The fixture returns plain values rather than serializing Window or reactive array proxies through CDP. Earlier fixture errors are retained in the workspace evidence directory.

The complete browser suite must still check actual source/CSS variable admission, ordering, cancellation, owner retirement, two-device projection, IndexedDB replay, stable DOM/images, streaming handoff and optimized Worker loading. A standalone policy test is not full application acceptance. The validation manifest separates fresh browser/application results from unchanged backend evidence.

First synchronous CBS and arbitrary regex/DOM operations can still monopolize the main thread. The task boundary does not preempt a running script, guarantee task order between independent rows, impose a script CPU budget or remove expensive native button startup. Headless Chromium/page throttling does not prove physical mobile or equal Worker throttling. Translation/inlay/aliases, complete extension/state contracts, offline/restore/import and all 15 configured-trial requirements remain active. Production and private content were not accessed.
