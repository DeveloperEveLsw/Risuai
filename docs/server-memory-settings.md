# 원본 전역 메모리 설정의 서버 저장

원본 기타 봇 설정의 장기 메모리 화면을 독립 초안과 서버 필드 명령에 연결한다. Supa/Hypa V2/Hypa V3/Hanurai의 원본 알고리즘과 프리셋 생성기는 변경하지 않는다. 일반 모드는 기존 DBState 저장 방식을 사용한다.

| 저장 단위        | 연결한 값                                                                                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모드 원자 그룹   | supaModelType, memoryAlgorithmType, hypav2, hanuraiEnable, hypaV3                                                                                                           |
| 독립 설정        | hanuraiSplit, hanuraiTokens, hypaAllocatedTokens, hypaChunkSize, hypaCustomSettings, hypaMemory, hypaModel, maxSupaChunkSize, supaMemoryKey, supaMemoryPrompt, voyageApiKey |
| 프리셋 원자 그룹 | hypaV3Presets, hypaV3PresetId                                                                                                                                               |

총 18개 전역 필드를 저장한다. 모드 관련 다섯 값과 프리셋 배열·선택 인덱스는 한 명령으로 제출하고 모두의 revision/epoch를 비교한다. 관련 값이 일부만 바뀌어도 원자 그룹 전체의 기대 버전을 포함한다. 프리셋 선택 자체도 배열의 버전을 확인하므로, 다른 기기가 목록을 삭제하거나 바꾼 상황에서 오래된 인덱스를 적용하지 않는다. 같은 그룹 동시 변경은 충돌로 보존하며 자동으로 합치지 않는다.

추가·이름 변경·삭제·JSON 가져오기와 내보내기는 원본 버튼을 사용한다. 확인창과 파일 선택 전에 배열·선택값·버전을 캡처한다. 기다리는 동안 값이 변경되거나 A→B→A로 돌아온 경우 이름 변경/삭제/가져오기를 거절한다. 접수 후 경합은 내구 outbox의 충돌로 표시하고 서버 값 또는 사용자 변경을 명시적으로 선택한다.

읽기 투영에서 원본 기본값/타입 정규화를 적용하면서 기존 서버 프리셋과 custom embedding 설정의 알 수 없는 멤버를 보존한다. 화면을 열 때 서버에 기본값이나 비율 정정 값을 쓰지 않는다. 비율 합계가 1을 넘으면 사용자의 최근/유사 메모리 슬라이더 수정 시에만 다른 비율을 조정한다. 일반 모드는 기존 자동 비율 정정 효과를 유지한다.

원본 JSON 가져오기 생성기는 알려진 설정의 타입만 허용하고 입력 파일의 알 수 없는 멤버는 제거한다. 이는 원본 가져오기 정책이다. 이미 저장된 프리셋의 알 수 없는 멤버는 편집·내보내기에서 보존한다. 프리셋 설정은 배열 전체, custom embedding 설정은 객체 전체의 필드 저장이며 프리셋별 관계형 행이나 항목별 병합은 아직 지원하지 않는다.

브라우저 검증은 `node --test server/browser/memorySettingsUi.test.cjs`로 실행한다. 공개 소스와 자체 합성 데이터, 독립 프로필, loopback 가상 공급자만 사용한다. 전체 재검사는 루트의 `python3 scripts/verify_memory_settings.py`를 사용하며 새 실행 label로 기존 로그를 보존한다. 실물 모바일·실제 사용자 데이터·일반 모드 기능 수락·전체 메모리 알고리즘 조합을 검증한 것으로 간주하지 않는다.

Hypa V3 대화별 요약/카테고리/태그/병합/재요약 모달은 이번 전역 설정 포트의 범위 밖에 남아 있다. 재요약은 탭 종료에도 유지되는 서버 작업과 소유권 검사가 필요하다. 에셋·플러그인·전체 읽기 출처/저장 예산·대형 HTML/Worker/cold 측정·실물 모바일·사용자 수락 및 기존 15개 완료 조건도 계속 수행한다. 사용자 지시에 따라 추가 TTS 개발·검증은 제외한다. 운영 서비스 접속/배포, 개인 자료 열람, 실제 모델 요청, 원격 push는 하지 않는다.
