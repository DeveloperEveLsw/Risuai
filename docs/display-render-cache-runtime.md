# Bounded pure display formatting reuse

Entity-mode ChatBody now retains one immutable Markdown result and one sanitized result for its mounted owner. It always runs the original asset resolution, Lua, regex and CBS before checking the exact processed source and formatting policy. Fresh captures, read provenance, proposals, CSS CBS and final admission are never cached. An unchanged output does not prove that an original script is pure.

Markdown policy includes the effective four quote strings, quote formatting, blockquote styling and the error label used by highlighted error blocks. Sanitizer reuse additionally requires the exact final HTML input and image-hiding setting. Invalid quote shapes and configured plugins bypass reuse. Failed math rendering or highlighting is not remembered, so subsequent executions retain their original retry/error behavior. Formatting in the legacy runtime is unchanged.

Any case-insensitive `risu-style` marker bypasses sanitizer reuse. Its current CSS CBS must run again and contribute its reads to the existing final admission. Reusing the earlier pure Markdown string does not authorize stale CSS or persistent effects. A different translated or watermarked input is sanitized independently. Existing owner cancellation and atomic variable/source admission still run after formatting.

The shared LRU pool bounds retained cached strings to 16 MiB, 256 owners and 512 KiB per owner. Sizes conservatively count each stored UTF-16 string, including the source, policy and sanitizer input. These are cache retention bounds, rather than a bound on DOM, transient allocations or total browser memory. Oversized results evict their preceding entry. Destroying a mounted ChatBody releases its entry; closed owners cannot retain a later async result. Entries do not retain captures, drafts, DOM nodes, assets or presentation promises.

The real original parser/UI/Worker scenario checks repeated stateful Lua calls with identical output, quotes, MathML, highlighted error blocks, sanitizing a changed finalizer input, authoritative setting changes, fresh CSS variable changes and navigation. It observes two mounted owners become one and retained cache strings fall from 3,640 to 324 bytes after navigation in its small synthetic fixture. Unit checks cover exact policy/input matching, CSS bypass, LRU and size bounds, stale tickets, the default shared pool and close fencing.

In the paired six-observation synthetic comparison, the page with a 4x CDP CPU delay reduced Markdown entries from 108 to 63 and sanitization entries from 57 to 12 per toggle. All 56 Lua calculations and all 44 unaffected-row calculations remained. Observed p95 settling changed from 1,560.7 to 1,444.6 ms; checkbox feedback from 56.4 to 53.8 ms. Maximum frame gaps remained large, 383.3 versus 366.6 ms. Desktop p95 feedback and frame gaps did not improve. Two entry counters measure actual renderer calls without changing fixture HTML or script behavior. The full regression also runs without those counters.

This establishes less repeated pure formatting work, not a universal speed or stutter guarantee. The fixture has 50 rows, 2,400 HTML cells, 16 regex rules, 269,190 source bytes and 600,000 loop iterations per counted Lua call. The comparison uses warm headless development builds and six samples per scenario. CDP delays the page target; worker CPU throttling is not verified. A physical mobile OS, arbitrary plugin behavior, all render policies and large changed HTML are not certified by this comparison.

Stateful Lua dependency semantics, remaining synchronous outer parsing, changed-HTML descendant preservation, translation/inlay/asset ownership, offline/restore and the complete configured trial remain required. All 15 requirements in `server-runtime-plan.md` remain active. Production was not accessed or changed.
