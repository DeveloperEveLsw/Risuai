## Architecture decisions

- Browser: Svelte DBState as the confirmed partial read model, plus device navigation and a separate pending operation layer. Display processing runs locally without duplicate persistent writes.
- State service: entity commands, durable admission, revisions, SQLite transactions and a durable ordered change log. No whole-DB replacement during ordinary operation.
- Engine: explicit character/chat/job/config context. Preserve the original prompt, CBS, regex, trigger and Lua semantics while separating browser capabilities. CPU-heavy engine work runs outside the HTTP thread. Persistent changes are committed as a bounded write set.
- Scheduling: one ordered execution stream per chat; independent chats may run together after shared dependencies are isolated. Shared/global script effects require explicit coordination, not silent last-writer overwrites.
- SQLite runs in its own worker. The local Node 22 runtime supports node:sqlite, currently experimental; driver usage is encapsulated and will be reviewed against the pinned deployment runtime before release.
- Provider calls are outside database transactions. Browser disconnect is not cancellation. An uncertain external call after server failure is interrupted, not automatically repeated.
