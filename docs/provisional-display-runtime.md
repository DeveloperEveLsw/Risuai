# Pending and native progress display

The entity UI now processes owned pending inputs and native partial messages before the generation transaction is persisted. The original `off` and `balanced` modes retain CBS, regex, Lua, Markdown and asset processing. No mode is forced to raw streaming, and canonical source/admission guards stay intact.

Previously `captureDisplayHeader` rejected every noncanonical message ID. The parser then had no owned capture, and the Markdown owner correctly deferred rendering. A valid pending row could therefore remain empty until generation completed even though the native server had already published text.

The controller now shares one overlay selector between presentation and provisional capture. Only unblocked sends from the active chat incarnation and nonterminal jobs from that incarnation qualify. Canonical IDs win. Unknown, foreign, blocked, expired, terminal and historical-window sources cannot gain a preview capture. The existing ready, projected cursor, input clock, history cursor and selected-character fences apply, with explicit chat/character incarnation checks.

The scripting adapter forks the pinned canonical display cache, then appends fresh private preview bodies to that fork. Canonical ordinals and unloaded gaps remain unchanged; preview ordinals follow the complete canonical count in presentation order. Original CBS/Lua can see these temporary rows and their lengths. Unloaded canonical history still fails explicitly. These ordinals belong to the current preview and can change when pending rows or canonical history change.

Preview sources have revision zero, `persistent=false` and a provisional read ledger. Original display setters have private read-your-writes, and an own-source text rewrite stays private. They cannot enqueue persistent display effects. Once the real canonical revision exists, the ordinary captured-source path computes and admits its own effects under the existing revision/incarnation/deduplication rules. This does not save partial generations or make an incomplete failed job recoverable.

Fresh nested preview fields are pinned before asynchronous work. Equal rows reuse weakly held immutable arrays/windows; changed text and unknown metadata produce fresh snapshots. Mutable variable maps and aliases remain private per fork. Original VM globals, callback ordering, budgets, cancellation and capability errors are preserved. Streaming can run original display scripts repeatedly; expensive or stateful scripts can still cost time or show a different final result. This change removes a mandatory wait for canonical persistence, not those computation costs.

Validation uses authored fixtures and actual Wasmoon/CBS, the compiled controller, and the real original UI with a gated loopback native provider. Both modes show the pending input while HTTP admission is paused, process partial output and decode its PNG while completion is held, synchronize a toggle between independent browser contexts, retain the actual rows/image through another delta and canonical completion, and submit no preview effect before completion. The raw submitted command remains intact; normal native input CBS processing determines the canonical input text. Foreign/blocked/incarnation/history fences, private source rewrites, unloaded gaps and equal/changed snapshot identity have separate checks.

All15 requirements/check states remain unchanged and active. Production access, installed/private content reads, real provider calls, deployment and remote push are absent from this follow-up. Physical mobile, representative latency/long tasks, full extension/read/write/storage contracts and complete user acceptance remain required. The local trial still defaults to `strong`; these checks explicitly configure `off` and `balanced`.
