# Original manual bookmark actions

The original Chat menu now adds/removes bookmarks through canonical member commands. BookmarkList renames/removes use the same path. The browser reserves a shared private preparation before the first header await, then captures the saved owner, message revision, chat epoch and member revision before opening the original name dialog. A selection change during header preparation rejects without opening a dialog. Closing BookmarkList during that await also retires its late dialog and releases preparation. A selection change after the dialog opens preserves its original target. A removed Svelte proxy name may still satisfy Object.hasOwn while the in operator reports absence. Capture requires both checks, preventing undefined JSON failures on re-addition. Neither preparation nor pending name/selection writes the confirmed DBState collections.

Preparation and IndexedDB intent provide pressed/busy/disabled state and pending names across the original controls. Blocked requests no longer supply provisional names/selection; the canonical value and existing error/review remain visible. Add with blank input retains the original generated default name. Rename with blank input releases preparation without a command. Both menu and list removal retain the original remove-first duplicate semantics.

The preparation pins the fully projected cursor or newer chat metadata snapshot cursor before its first await. The body-free header accepts that observedCursor and checks a partial per-member journal index for later bookmark changes in the same read transaction. Removal and re-addition with an identical name therefore reject instead of rebasing an old click. A cursor outside the retained journal fails with RESYNC_REQUIRED. The optional argument leaves existing header callers unchanged; the index adds no schema-version or data rewrite.

The header read also compares the click's confirmed message/name/presence with the returned canonical header, so a newer header cannot silently tag older UI text. Same-member name/body/epoch changes after input capture reject at server admission. Changes to a different bookmark remain independent. Commands contain IDs, revisions, action and name, with no message body. Expanded original previews for loaded list members now receive their persistent message ID.

## Acceptance scope and remaining work

The synthetic original UI fixture directly clicks the original menu, name input and list controls in two independent browser contexts. It checks held header/POST states, canonical facade separation, generated defaults, cancelled rename, independent members, stale name/body conflicts, same-value removal/re-addition before header completion, both selection races, loaded preview identity, stable neighboring rows, metadata projection without snapshot reads, reload and once-only removal replay after every tab closes. This differs from the earlier generic enqueue protocol fixture, which remains a separate server-contract check.

BookmarkList still resolves only the loaded history window. The existing bounded canonical page API must next supply the full bookmark list, outside-page original HTML previews with explicit source provenance and stable-ID jump/pagination. Full-history branching, folders/reference policy, remaining manual editors, extensions/offline/restore/physical mobile and the complete configured user trial remain required. All 15 original completion requirements stay active. This manual-action milestone does not complete the entire bookmark feature or goal.

Only authored neutral synthetic data and public development source are used. Production access, private-content import, deployment and remote push remain outside this work.

The local CLI uses a dedicated Vite dependency cache (or RISU_RUNTIME_UI_CACHE_DIRECTORY). The disposable smoke sets an owned cache directory and verifies its removal with the temporary database. A concurrent CLI/browser run had one initial App/Svelte-context boot failure before archive acceptance; its log is retained. Cache sharing is a plausible interference source, not an established causal diagnosis. Final acceptance runs the CLI smoke and full browser suite in sequence.
