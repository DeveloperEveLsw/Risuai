# Isolated native runtime API

This is the local server integration layer for the existing Risu UI. The browser transport/outbox, first setup and scoped character/chat lifecycle are integrated; complete configuration/resource management/import/export and mobile acceptance remain unfinished. `pnpm dev:entity` starts the development UI as well as this API. The full practical user trial remains unfinished. See `browser-runtime-protocol.md`, `risu-browser-integration.md` and `character-chat-lifecycle-runtime.md` for client contracts and verified scope.

The tested runtime is Node 22.21.0. Node's SQLite and VM tokenizer loader APIs are experimental. The default database is a new `.local-runtime/entity.sqlite` under this checkout; no existing production save, profile or credential is imported. The development listener binds to `127.0.0.1` and defaults to port 6174.

```sh
pnpm dev:runtime
```

`RISU_RUNTIME_PORT`, `RISU_RUNTIME_DATABASE` and `RISU_RUNTIME_CONCURRENCY` override the isolated port, database path and worker limit. The default concurrency is two. The command builds the native entry before starting the service. Ctrl+C stops it. Production authentication, remote hosting and deployment remain separate release gates.

```sh
curl --fail http://127.0.0.1:6174/api/runtime/health
curl --fail http://127.0.0.1:6174/api/runtime/bootstrap
```

Schema v5 assigns a stable UUID to each server database. Bootstrap returns `serverId`; the browser transport pins that identity in the `Risu-Runtime-Id` header. A mismatching database rejects admission with `SERVER_CHANGED` before mutating data. This is identity fencing for pending commands, not production authentication.

Every endpoint is under `/api/runtime`.

Schema 12 adds durable `apply-display-effects` admission and paginated `GET /chats/:id/display` receipts/input clocks. The server checks source/identity/read/write revisions and stores a logical display effect once across different transport IDs. Original browser Lua display calls are not wired to this boundary yet; the direct DBState gap remains. See [display-effect contract, duplicate semantics and integration limits](display-effects-runtime.md).

Schema 11 adds shared immutable asset metadata and separate durable blob files. `POST /assets?extension=png` accepts a bounded raw binary body with the current runtime identity; `GET /assets/:id?authority=SERVER_ID` supplies stable cacheable media URLs, conditional reads and byte ranges. Preserve the database and `<database file>.assets/<serverId>/` together. `set-persona-image` guards original selection/resource/icon versions before attaching an admitted asset; `record-import` adds original binary import attempts without duplicate increments on retry. Original persona PNG and synthetic character v2/v3 PNG roundtrips are exercised locally; full asset/archive/picker/native/offline capability coverage remains unfinished. See [shared asset contracts and evidence](shared-assets-runtime.md).

| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /bootstrap`                                         | Persisted server identity, character summaries, resource IDs/revisions, counters and a consistent change cursor; no message archive. |
| `GET /characters/:id`                                    | One definition, activity, field headers, chat summaries and cursor in a consistent WAL read; no message archive.                     |
| `GET /characters/:id/chats`                              | Chat summaries for one character.                                                                                                    |
| `GET /chats/:id?limit=100&before=POSITION`               | A consistent chat snapshot, variables, message page and cursor.                                                                      |
| `GET /resources/:kind/:id`                               | One resource body, own field headers, epoch and cursor in a consistent WAL snapshot.                                                 |
| `GET /libraries/:kind?limit=50&search=TEXT&after=CURSOR` | Bounded summary catalog page and cursor; no definition bodies.                                                                       |
| `POST /libraries/module/resolve`                         | Exact ID/namespace lookup returning matching compact module summaries.                                                               |
| `POST /variables/read`                                   | Consistent requested variable values/revisions/cursor, including deletions; no message history.                                      |
| `POST /fields/read`                                      | Consistent requested entity fields, own revisions, presence and incarnation epochs; no message history.                              |
| `POST /commands`                                         | `{requestId, command}`; returns only after the bounded entity mutation and journal entry commit.                                     |
| `POST /jobs`                                             | `{requestId, command}`; returns HTTP 202 after durable admission, before engine completion.                                          |
| `GET /chats/:id/jobs`                                    | Recent job summaries without growing response bodies.                                                                                |
| `GET /jobs/:id`                                          | Job state, separate recoverable progress and terminal result.                                                                        |
| `GET /jobs/:id/command`                                  | Stored input/intent for a new device reconstructing an unknown pending job.                                                          |
| `POST /jobs/:id/cancel`                                  | Explicit cancellation, independent of closing HTTP or SSE connections.                                                               |
| `GET /changes?after=CURSOR`                              | Ordered paginated durable changes.                                                                                                   |
| `GET /events?after=CURSOR`                               | SSE replay followed by live changes; `Last-Event-ID` takes precedence on reconnect.                                                  |

The current entity commands are `create-character`, `create-chat`, `clone-chat`, `delete-chat`, `delete-character`, `append-message`, `edit-message`, `set-chat-variable`, `change-variables`, `change-fields` and `put-resource`. Schema v9 retains content/map-range and own field revisions/epochs, adds compact trash/chat-order summaries and separates retained job history from live chat lifetime. Original sidebar/common settings, the model page, first setup and basic character/chat controls have durable integration. Other manual controls/editors and resource management still need commands. See [character/chat lifecycle](character-chat-lifecycle-runtime.md), [entity fields](entity-fields.md) and [variables](variable-runtime.md) for guards, atomic batches, predecessors and pinned execution semantics. Job types are `send`, `continue`, `reroll` and `button`. Continue/reroll identity and complete variant handling still need acceptance work. Native generation currently verifies completion and Responses API routes and their upstream processing; additional providers/capabilities and extension lifetime compatibility remain in scope.

The development launcher installs upstream default settings and split resource rows once in an empty authority. Existing or intentionally deleted global settings are preserved. Bootstrap includes compact trash/epoch summaries and character/chat lifecycle tombstones. Jobs can carry `expectedChatEpoch` on admission; listings and presentation fence old incarnations. Terminal job/command receipts remain queryable after chat deletion, while accepted queued/running jobs prevent deletion.

Library commands `save-library-resource`, `delete-library-resource` and `reorder-library` manage module/preset/persona/plugin rows and related membership/selection/global enable fields atomically. They require explicit revision/epoch guards. `activate-library-resource` and `save-active-library` add atomic preset/persona capture and application using original helpers and strict selection/incarnation guards; observed resource revisions allow current same-incarnation data. The original module, preset and persona controls are connected, including the original preset import/export path. Shared server assets and original persona/character PNG paths are connected and checked with synthetic fixtures. Plugin management, full archive/asset formats, file-picker and native image capability coverage remain unfinished. Schema v10 adds transactional compact catalogs and consistent body snapshots. The module page uses summaries and lazy active/edit bodies; preset/persona UI and bootstrap still retain full resource arrays. See [library resource contracts](library-resource-runtime.md), [selection contracts and pending/conflict behavior](library-selection-runtime.md) and [catalog contracts/measurements](library-catalog-runtime.md).

For a send, the browser should allocate and persist both a `requestId` and `messageId` before submission. Retrying the same ID and payload returns the existing job; a different payload under that ID returns an idempotency conflict. Closing a browser observation connection does not cancel a job. A lost acknowledgement must be reconciled by the original ID rather than creating another paid request.

The supervisor takes lightweight claims containing only the job and command. Full history/resources are read in a consistent WAL snapshot on the engine worker, after verifying ownership and the starting content revision. Variable edits between claim and snapshot acquisition are included; later edits do not change that job's private baseline. Modern final writes fence content and each changed variable independently; legacy final formats retain the full-chat guard. The legacy in-process claim helper can still include a snapshot for existing tests. Resource versions are pinned at execution snapshot acquisition; cross-character lazy resolution must match those pinned definition versions.

Streaming message updates are observed in all three upstream modes (`off`, `balanced`, `strong`), independently of browser animation callbacks. Progress is coalesced and checkpointed separately from canonical messages. `job-progress` journal events contain a job ID and progress revision; clients fetch the latest body only for relevant jobs. Completed messages are read from canonical chat data. Failed/interrupted progress remains a recoverable artifact and must not be presented as a saved complete reply.

Ordinary `change-fields` and compatible native point writes publish `fields` events containing only changed values, presence, own revisions and epochs. Legacy whole-entity writes keep their existing events. Large changed values are still inline; no general bounded-reference protocol is claimed.

SSE clients start from the snapshot cursor. Sequence IDs permit replay of changes that occurred between snapshot acquisition and subscription. Expired/future cursors require another partial snapshot. Slow-client buffers are bounded by closing the stream; reconnection replays from the last received ID. The browser transport implements cursor replay and durable pending reconciliation. The scoped Risu DBState adapter and existing UI are connected; complete editing/imports and remaining compatibility work are unfinished.

The supervisor maintains leases while native CPU work runs. Cooperative cancellation aborts provider reads; non-cooperative workers are terminated after a grace period, with ownership checks preventing partial canonical writes. An expired/crashed worker becomes interrupted, preserving checkpointed output; potentially paid calls are never automatically replayed. Queued requests survive a service restart and resume under normal per-chat ordering.

Validation uses temporary SQLite databases and loopback synthetic providers. Eleven actual HTTP tests cover acknowledgement loss/idempotency, same-chat order and different-chat independence, partial reads/SSE handoff/reconnect, stream observation disconnect in all modes with stable final IDs, crashed-worker output retention, queued restart recovery, provider-read cancellation, cancellation of a verified non-cooperative Lua loop while another chat mutation completes, and development-origin/cursor validation. Four additional entity tests cover lean claims, progress persistence/fencing, interruption and schema-v3 migration to v4. These are not real-browser tab-exit, mobile, provider or latency acceptance results.

Original CharX/JPEG and legacy/current module package paths use the same shared asset API, with format propagation, JSON-compatible conversion and canonical installation only after successful extraction. See [archive contracts and acceptance limits](archive-runtime.md).
