# Stable display descendants and image ownership

Entity ChatBody now updates already sanitized HTML inside a private sibling range in the original `chattext` element. It adds no wrapping element. Other Svelte children and comments remain outside that range. An unchanged HTML string performs no DOM work. Destroying the owner removes only its range, and a closed owner ignores later updates. The original legacy HTML branch remains available.

The renderer matches unique sibling IDs and compatible elements at unchanged positions. It updates changed attributes and text while retaining unchanged image/input/textarea nodes. Authored attributes are tracked separately from live browser state: an unchanged authored image source retains its resolved URL, and neighboring text changes retain local typing, checkbox state, focus and selection. An explicit authored value/checked/selected change still updates the control. Changed IDs or namespaces receive fresh nodes. External classes survive changes to authored class tokens.

This is an ownership policy rather than a universal arbitrary-DOM equivalence guarantee. Ambiguous duplicate IDs fall back to compatible positions. Elements are not moved across parents or owners. The diff stops descending after depth 128 and replaces the deeper subtree, preventing JavaScript recursion exhaustion; local state below that fallback is not preserved. Traversal for new-node metadata is iterative. Arbitrary plugin DOM mutations, contenteditable selection, all table/parser contexts and media playback policy still require their own acceptance.

A real two-device negative control on commit `d6577b8` retained the message row but replaced its image and input after the other device clicked the original toggle. The first device lost its typed value, focus and selection. The current original UI keeps those descendants and the local value/selection while reflecting the confirmed toggle. Unit checks also cover explicit server values, resolved image URLs, sibling insertion/reorder, SVG namespaces, distinct owners, close fencing and the deep-tree fallback.

The original named-image resolver now fences both exact and prefix lookup completions with the captured DOM root, parsing epoch, connection and unchanged source. A new authored source clears its previous transient `noimage`/loaded-image decoration. Canonical relative `/api/runtime/assets/` URLs are excluded from named lookup. This corrects an intermediate candidate failure where rechecking a resolved URL set `noimage`, which then survived a source change and prevented a later lookup.

The actual UI image scenario uploads and decodes synthetic PNG assets through the existing HTTP path. Only the original URL capability is delayed. A later image source resolves and retains the same node; releasing the old lookup cannot overwrite it. A second held lookup released after character navigation cannot mutate its detached image. This proves the tested ownership boundaries, without claiming that all asynchronous assets, aliases, translations or inlays share that lifetime.

Original codeblock observation also had a lifetime fault: a 100 ms polling loop repeatedly attached listeners, and repeated initialization started more loops. A real original codeblock produced 5, then 17, then 22 menu creations per context-menu event; removing its marker still left 22 handlers active. One idempotent MutationObserver now scans added subtrees and the two relevant attributes. Weak metadata and AbortController retire the previous handler when its marker changes or is removed. Actual UI checks observe one menu per event after repeated starts/metadata changes and zero after marker removal. Copy/download operations remain. The first connected BGM marker still repeats after an ended track using one 100 ms retry, and the current marker's source/volume is read again. Neutral EventTarget audio fixtures verify repeat, metadata change and removal; they do not establish actual audio decoding/autoplay acceptance.

Validation and source fingerprints are recorded in `docs/local-validation.json` and the workspace `evidence/display-dom-validation.json`. Original DOM and observer negative controls, intermediate image/type diagnostics and earlier completed evidence remain separate. Representative latency remains limited to synthetic development-browser observations; this change does not claim universal elimination of long tasks or certify a physical mobile OS.

Translation/inlay/alias/reference lifetime, persistent outer extension policy, offline/restore, the remaining configured trial and all 15 requirements in `server-runtime-plan.md` remain active. Production was not accessed or changed.
