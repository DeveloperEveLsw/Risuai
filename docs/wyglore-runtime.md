# WygLore Leaf 원본 플러그인 서버 호환

WygLore Leaf 3.1.6의 원본 기억 처리와 설정 핸들러를 서버의 별도 프로세스에서 실행한다. 브라우저는 원본 설정 화면의 안전한 DOM과 CSS를 표시하고 입력을 전달한다. 알고리즘을 별도로 재구현하거나 브라우저에 두 번째 기억 엔진을 실행하지 않는다.

## 지원 대상과 실행

제작자 공개 저장소는 <https://huggingface.co/m6dd8m/wyglore-leaf>이다. 다음 배포본만 허용한다.

- 버전: 3.1.6, Risu 플러그인 API 3.0
- 공개 소스 revision: `f028901324a87053ea72b361073744900aabc763`
- 원본 JS SHA256: `5829457ed4a8b63a5c61b0048aa2b5cb53837b4652c6907077d97cc54cfb2d9c`

수입·저장되는 원본 JS는 그대로 유지한다. 서버 실행 사본에는 원본의 준비·패널 동기화·저장 완료를 기다리는 lifecycle 연결 코드, 원본 확인창 26곳의 사용자 선택과 지연된 모델 설정 저장을 기다리는 연결 코드를 추가한다. 관련 함수의 SHA·AST 위치와 Promise를 반환하는 호출자도 검사한다. 동기 함수 3곳의 async 전환, 확인 helper 호출 2곳의 await, 수동 복구 호출자 2곳의 return이 포함된다. 실행 사본까지 원본과 바이트가 같다는 의미는 아니다. VM은 검토한 고정 번들의 실행 환경이며 임의의 플러그인을 안전하게 실행하는 범용 보안 sandbox로 취급하지 않는다.

서버 지원은 기본적으로 꺼져 있다. 격리된 로컬 데이터로 시작하려면 저장소 루트에서 다음을 실행한다.

```bash
pnpm build:native
RISU_REVIEWED_SERVER_PLUGINS=TRUE \
RISU_RUNTIME_DATABASE=.local-runtime/wyglore-trial.sqlite \
pnpm dev:entity
```

UI 주소는 `http://127.0.0.1:5174`이다. 원본 플러그인 파일을 기존 플러그인 가져오기 기능으로 수입하고 활성화한다. 캐릭터의 채팅을 선택한 상태에서 설정의 플러그인 페이지에 있는 **WygLore Leaf 설정 열기**를 누른다. 원본의 모델·API 설정과 자동 기억 처리 옵션은 사용자가 선택한다. 모델을 호출하는 원본 작업에는 평소처럼 API 비용이 발생할 수 있다.

검증용 원본은 저장소에 커밋하지 않으며 테스트가 임의로 다운로드하지 않는다.

```bash
node server/native/wygloreContract.cjs fetch
node server/native/wygloreContract.cjs verify
```

새 배포본이나 수정된 번들은 같은 이름이라도 허용하지 않는다. 갱신하려면 공개 코드와 호환 계약을 다시 검토해야 한다.

## 실행과 저장의 경계

| 영역      | 구현                                                                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 생성      | 서버 작업이 원본 before/after 훅을 실행한다. 일반 응답과 스트리밍에서 동일한 훅과 저장 경계를 사용한다.                                                          |
| 기억      | 플러그인 namespace에 한 writer만 허용한다. 원본의 여러 저장 키는 private overlay에 모으고 완료된 작업의 채팅 변경과 함께 하나의 SQLite transaction으로 확정한다. |
| 설정 UI   | 원본 `registerSetting` 콜백과 이벤트 핸들러를 서버에서 실행한다. 브라우저의 opaque iframe에는 원본 JS가 실행되지 않는다.                                         |
| 두 기기   | 기존 writer와 같은 기억을 동시에 수정하는 새 설정창은 거부한다. 생성은 단일 writer 순서를 지키고 시작할 때 최신 source snapshot을 다시 받는다.                   |
| 탭 종료   | 서버가 접수한 생성과 UI 작업은 브라우저 polling 없이 계속된다. 설정창을 닫으면 접수한 UI 동작을 완료한 뒤 owner를 정리한다.                                      |
| 새 생성   | 기존 UI 동작이 끝나도록 기다린 뒤 설정창 owner를 닫고 새 작업을 승인한다. UI가 공유 writer를 잡은 채 생성이 기다리는 상태를 막는다.                              |
| 취소·충돌 | 취소, 작업 lease 만료, 캐릭터·채팅의 삭제/재생성, 읽은 설정·모듈·페르소나·변수 변경을 확인한다. 불완전한 기억을 canonical DB에 저장하지 않는다.                  |
| 응답 유실 | UI 이벤트 ID와 완료 영수증을 조회한다. 이미 끝난 동일 요청의 확인은 가능하지만, 결과가 불확실한 모델 호출이나 핸들러를 자동 재실행하지 않는다.                   |

원본 패널이 비동기로 이전 설정을 읽는 동안 새 입력을 덮어쓰던 경로는 패널 동기화를 기다려 해결한다. 기본 `<details>/<summary>` 펼치기는 실제 MouseEvent 기본 동작을 전달한다. 브라우저의 키가 있는 DOM 갱신은 입력 중인 값, 포커스, 선택 범위와 스크롤을 유지한다.

원본 기억 카드·나이테·관계 목록에서 카드의 추가·편집·저장·재열기를 지원한다. 입력 listener 없이 저장 버튼이 `.value`를 읽는 원본 폼도 실제 값을 전달한다. HappyDOM 20.1.0이 옵션 삽입 시 잘못 바꾸던 선택 상태는 해당 private DOM owner 안에서 보존한다.

모델 설정 탭은 원본이 요구하는 캐시 설정 네 개를 실제 서버 settings snapshot에서 읽고, 해당 revision·epoch의 변경을 최종 저장 전에 검사한다. 모델 이름의 250ms 지연 저장과 API 필드의 400ms 저장 큐는 원본 `flushSave`와 `providerFieldSaves.flush()`로 완료한 뒤 이벤트를 저장한다. 임의의 타이머를 실행하거나 고정 대기 시간을 추가하지 않는다. 입력 완료 응답 후 즉시 창을 닫고 다시 열어도 값이 유지되는 실제 Chromium 회귀 검증을 포함한다.

파일 내보내기는 원본 JSON/Blob 생성 코드를 사용한다. 대화·기억 checkpoint가 성공한 뒤에만 현재 owner가 파일을 받을 수 있다. 브라우저 요청 영역에서 다운로드를 눌러 저장한다. 설정·전체 기억뜰 가져오기는 파일 선택과 명시적 덮어쓰기 승인 후 원본의 검증·가져오기 함수를 실행한다. 파일과 전송 데이터는 UTF-8 8 MiB, owner당 4개 요청·합계 8 MiB로 제한한다. 이 파일은 원본 형식이며 플러그인의 API 설정도 포함할 수 있다. 다른 owner·DB·이벤트에서는 받을 수 없다.

파일 선택·검토한 확인창을 취소하거나 설정창을 닫으면 대화와 기억을 바꾸지 않고 접수된 이벤트의 영수증만 완료한 뒤 해당 원본 인스턴스를 정리한다. 이후 편집은 창을 다시 열어 진행한다. 다운로드 자료는 owner 수명 동안만 보관하며 서버 재시작 후 자동 재실행하지 않는다. 클립보드 쓰기는 브라우저의 복사 버튼이 실제 쓰기를 확인해야 원본 Promise를 완료한다. 클립보드 읽기·바이너리 파일은 지원하지 않는다.

원본의 기억 식별 키는 UI와 생성 양쪽에서 같은 실제 캐릭터·채팅 인덱스로 계산한다. 다른 채팅의 본문은 UI catalog에 포함하지 않는다. catalog는 ID·이름·페르소나 연결·첫 메시지 ID·기억 marker만 포함하며 원본의 정리·이름 표시를 위한 제한된 읽기 계약이다. 다른 채팅의 원문 읽기나 쓰기를 제공하는 일반 `getDatabase().characters` 구현은 아니다. 전체 catalog는 4,096행과 정해진 크기 제한을 넘으면 일부만 반환하지 않고 거부한다.

## 백업과 복원

저장 스키마는 21에서 22로 확장된다. 기존 캐릭터·채팅·메시지 데이터와 서버 ID를 보존하는 additive migration이다. 플러그인 기억과 완료 영수증은 완전한 서버 snapshot에 포함한다. snapshot 복원은 실행 중 writer lease를 재사용하지 않는다.

플러그인 기억이 있으면 기존 JSON archive만으로 완전한 백업을 만들 수 없으므로 해당 export를 명시적으로 거부한다. 서버 snapshot을 사용해야 한다. 스키마 21까지만 지원하는 이전 운영 코드로 되돌리려면 migration 전 백업이 필요하다. 이후 새로 저장한 대화와 기억은 별도로 보존해야 하며 구버전 코드로 스키마 22 DB를 그대로 여는 방식은 지원하지 않는다.

## 현재 범위

원본 기억 주입·생성 후 처리·저장·기본 설정 UI를 실제 원본 번들로 검증한다. 모든 플러그인 API 또는 모든 원본 화면 기능을 지원한다는 뜻은 아니다.

- 고정 원본의 확인창 26곳은 브라우저의 명시적인 승인·취소를 기다린다. 대규모 맥락 따라잡기·손실 복구·파일 가져오기의 취소와 승인 대기 중 source 충돌을 검증했다. 확인창 연결이 모든 고급 작업의 전체 실행 검증을 뜻하지는 않는다. 검토하지 않은 새 동기 확인 호출은 실패한다.
- 이 원본 버전의 기억 화면은 canvas 지도가 아니라 HTML 카드·나이테·관계 목록이다. 도움말은 원본 handler와 내용을 유지하고, 브라우저에서 실제 anchor·viewport 위치를 계산한다. 위쪽과 화면 오른쪽 아래의 실제 배치를 Chromium으로 검증했다.
- 서버에는 앱의 main document가 없어 CBS 부동 위젯을 지원하지 않는다. 원본이 제공하는 비상 비활성화 플래그를 실행 realm에서만 읽어, 기본값 `true`의 3초 지연 mount가 서버 기억 엔진을 오류 상태로 만들지 않도록 한다. 저장된 설정·기억·원본 JS는 바꾸지 않는다. CBS 설정 탭은 사용할 수 있다.
- UI는 click/input/change/blur/keydown을 전달한다. 브라우저의 실제 layout을 서버 DOM에 되돌려주는 기능은 없다.
- background 작업에도 원본 플러그인의 모델 처리 시간은 그대로 필요하다. 서버 이동이 모델 응답 속도나 모든 기억 연산 시간을 줄인다는 보장은 없다.
- 호환 검증은 공개 원본과 합성 캐릭터·합성 HTTP 모델을 사용한다. 실제 Vertex 및 사용자의 카드·운영 기억 데이터 조합은 이번 검증 범위가 아니다.

구체적인 검증 결과와 원본 15개 요구사항 보존 증거는 워크스페이스의 `reports/wyglore-runtime-implementation-20261010.md`와 `evidence/wyglore-runtime-verification-20261010.json`에 기록한다. 기존 서비스 배포·원격 push와 실제 운영 데이터 조회는 이번 작업에서 수행하지 않는다.
